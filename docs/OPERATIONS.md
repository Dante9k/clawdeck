# 运维手册

## 信任与访问

ClawDeck 使用 Docker socket，管理员具备宿主机级能力。单一管理密码适用于可信管理员，不提供租户隔离。默认通过本机地址和 SSH 隧道访问；需要公网访问时在已有 HTTPS 反向代理后运行，并设置 `COOKIE_SECURE=true`，代理保留原始 Host。不要把面板密码、OpenClaw token 或 API Key 写入 URL。

会话保存在内存中，最长 8 小时，面板重启后失效。修改 `.env` 密码后执行 `docker compose up -d --force-recreate clawdeck`，旧会话一并失效。反向代理下登录限速按代理连接来源计算；共享代理可能共享每分钟 8 次尝试限制。

## 日常运行

```sh
docker compose ps
docker compose logs --tail=100 clawdeck
```

面板自身日志限制为每文件 10 MB、3 份。审计日志另存面板数据卷，5 MB 轮换一次，保留一份 previous。操作去重记录保留 24 小时，清理在启动和提交新操作时进行；每 24 小时最多 1000 项。执行记录和备份不上传到其他服务。

OpenClaw 配置备份位于各实例配置文件同目录，名称包含 `.clawdeck-backup-`、时间和随机后缀。最近 50 份可从界面选择，更老的备份仍在磁盘。没有自动删除策略，需纳入现有状态卷备份与容量监控。备份含真实凭据，不应公开分享。

## 升级

1. 记录当前包版本和面板镜像 ID，按现有流程备份 `.env`、面板数据卷及每个 OpenClaw 状态目录。
2. 停止发起新操作，确认没有进行中的配置写入。保留现有安装目录和 Compose 项目名。
3. 将新版代码覆盖到同一安装目录，保留 `.env`，不要复制其他用户的 data 目录。
4. 执行 `docker compose up -d --build --wait`，重新登录，检查状态和操作记录。
5. 先在一个测试实例完成读取、校验、保存、恢复，再推广到其他实例。

从 v0.1 升级：未显式设置 managed=true 的自动发现实例会变为只读。补齐 label 并应用原 Compose 后管理。RC1 不迁移或删除原 OpenClaw 配置与旧备份。

回退面板版本时使用先前保留的代码或镜像，保持项目名和数据卷不变。面板回退不会自动撤销已写入的 OpenClaw 配置；应先按需恢复配置。常规停用执行 `docker compose down`，无需删除数据卷。

## 错误处理

| 提示/现象                                      | 处理                                                                                                |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 仅自动发现，禁止管理                           | 添加 managed=true label 并重新应用实例 Compose                                                      |
| Docker 无法连接                                | 核对实际 socket 路径、运行用户权限、Docker Engine 状态                                              |
| 自检校验不通过                                 | 在目标实例原环境检查 `openclaw config validate --json`；不要绕过校验                                |
| 单文件挂载无法写入                             | 改为挂载完整状态目录；先备份并按原部署流程迁移                                                      |
| `$include` / 符号链接 / OAuth / 外部 SecretRef | 在原配置系统管理；面板不强制展开或代管                                                              |
| 版本冲突                                       | 重新读取，核对其他修改后再次编辑，不自动覆盖                                                        |
| 另一项配置操作正在进行                         | 等待任务结束；若面板/实例曾异常退出，先确认没有写入进程，再由管理员清理精确的 `.clawdeck-lock` 文件 |
| 结果未知 / 待核对                              | 检查容器状态、最新配置与备份；不要直接重复操作                                                      |
| 操作成功但审计失败                             | 检查 `/data` 可写性、剩余磁盘容量；操作可能已经完成，不应直接重试                                   |
| 登录后界面显示连接中断                         | 展示的是最后一次读取的数据，不能据此断言实例当前状态                                                |

配置写入使用面板自己的排他锁与两次版本检测；其他工具不遵守该锁时，仍存在最后检查到原子替换之间的竞态窗口。批量编辑期间避免在 CLI、其他面板或自动脚本中同时写入相同配置。

## 接口集成

先通过同源 `POST /api/login` 登录并保留 HttpOnly cookie。所有非 GET 请求需要 `Content-Type: application/json` 与 `X-Clawdeck-Request: 1`。生命周期、保存和恢复请求建议传入 16–80 位字母、数字、短横线或下划线组成的 `Idempotency-Key`；一次逻辑操作复用同一编号。

主要接口：`GET /api/overview`、`GET /api/operations`；实例下的 `config` GET/POST、`preview` POST、`validate` POST、`diagnostics` POST、`backups` GET、`restore` POST、`logs` GET、`start/stop/restart` POST。修改配置和预览需要当前 revision。恢复载荷为 `{ "backup": "备份编号", "revision": "当前版本" }`。没有任意命令或删除容器接口。

`200` 表示已确认完成，仍应读取 `warning`；`409` 表示冲突或同编号进行中/待核对；错误响应中的 `status: "unknown"` 表示执行结果无法确认。查询操作记录或读取当前实例确认后，再作下一步处理。
